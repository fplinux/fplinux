FPLinux: ARMADA plays a 3D scene and measures how quickly it generates frames. It can synchronize screen brightness, keypad lighting and vibration where those effects are available. One scene cycle lasts 38 seconds.

Check [phone support status](/fplinux/phones/#support-status) for the physical effects available on your phone.

## Start

ARMADA is included in the system. Open **ARMADA** from the application catalog. It opens a setup screen and waits for you to choose **Start**.

Press <Key>Centre</Key> on a parameter to open its choices; selecting a value returns to the same setup row. Focus **Start** and press <Key>Centre</Key> to begin. **Options → Reset parameters** restores Auto rendering, Full screen, one cycle and all available effects. Your choices are remembered. Opening ARMADA from the catalog returns to setup; selecting it in Tasks restores its retained view.

The same application adapts to compact, portrait and landscape screens. **Standard** keeps the system bars and the title. **Full screen** shows the scene above the soft-key bar. Choose the screen mode before starting. Settings stay fixed throughout a run.

The renderer choices use the same [software and GPU support](/fplinux/apps/#choose-a-renderer) as other graphical applications. Auto selects an available renderer during preparation. A run explicitly requesting GPU reports an error when it cannot use it.

## Choose the run length

**Cycles** offers **1**, **2**, **3**, **5**, **10** and **Until stopped**. Five cycles take about three minutes and ten seconds. The scene uses the selected screen's drawing area and renders continuously while its animation and physical effects keep their normal timing.

Hiding ARMADA, losing foreground or changing the drawing area interrupts the run and records a result. Use **Repeat** from that result to start again.

## What you see and feel

The **Effects** checklist enables screen brightness, keypad lighting and vibration independently. Unsupported effects are omitted. Disabling a light effect leaves ordinary system lighting in control; it does not switch that light off.

Enabled effects follow the scene: daylight and LCD brightness change, and the keypad light and vibrator pulse. Their timing changes, not vibration strength. During the hardware act, the keypad light and vibrator spell `FPLINUX` in Morse code while the matching letter pulses on screen. The cycle ends with two seconds of water after the letters sink.

There is no soundtrack. On phones that vibrate through the speaker, its low vibration tone can be audible; see [Vibration](/fplinux/use/display-and-lights/#vibration).

## Read the result

The result identifies completion, stopping, interruption or a rendering error. It includes generated frames per second, active time, frame count and rendering times, followed by the actual renderer, resolution and other run settings. **Repeat** uses the same actual renderer and settings; return to setup to edit them. **Last result** appears on setup while a result is available in the open application.

Generated FPS measures how quickly the application produces frames. It is not the panel's refresh rate. GPU rendering times include reading back and converting the image for display. Compare runs with the same renderer, resolution, settings and build.

## Stop or exit

Press <Key>Right soft</Key> for **Stop** during a run. **Back** on the result returns to setup, where **Back** closes ARMADA.

Stopping, hiding or closing ARMADA clears its temporary physical effects and restores the current system lighting policy, including your latest brightness setting.
