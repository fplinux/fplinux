## Where the applications work

See the [application comparison](/fplinux/phones/#application-support) for a quick overview and [phone support status](/fplinux/phones/#support-status) for each phone's requirements and limitations.

## Install an optional application

Install the APK as described in [Packages](/fplinux/guides/packages/). In a RAM boot, an installed application lasts until the phone shuts down. On a [microSD system card](/fplinux/guides/microsd-system-card/), it stays installed until you remove it. No optional application starts by itself. Exit an application before you remove its package.

## Start an application

Open graphical applications from the [application catalog](/fplinux/use/session/#home-and-applications). For command-line tools, run their commands in the [USB shell](/fplinux/use/connect/); `--exec` returns when the command exits and shows its output.

Brightness control, ARMADA, TyrQuake, `fplinux-present` and the `fplinux-rotate` preview use the display directly. Follow the [direct-display procedure](/fplinux/use/session/#direct-display-applications) to stop the graphical session before starting them and restart it afterwards. Exiting one of these applications does not restart Home.

## Choose a renderer

ARMADA and TyrQuake accept `--renderer auto|software|gpu`. The default, `auto`, starts the GPU renderer when a supported hardware context is available and falls back to software if GPU initialization fails. The selected renderer is printed at startup. A rendering error after startup ends the application.

- `--renderer software` uses the CPU and works without Mesa installed.
- `--renderer gpu` requires the hardware renderer and reports an error when it cannot start.

GPU rendering is available on [Xiaomi Qin 1s+](/fplinux/phones/xiaomi-qin-1s-plus/#applications). Choose a renderer for the application you use; GPU mode does not guarantee a higher frame rate. Other supported phones use software rendering.

## Command-line behavior

The FPLinux image tools, brightness application, ARMADA and Quake launcher follow these command-line rules. FFmpeg uses its own syntax; see `ffmpeg -h` for help.

- `-h` or `--help` prints the usage and every option, then exits with status `0`. It does not open a device or start any work.
- An option value can follow a space or an equals sign: `--output FILE` and `--output=FILE` are the same. Values cannot be empty.
- The image tools accept a repeated value option and use its last value. Every occurrence must still be valid. The other applications reject a repeated option.
- A command-line error prints the command name and the problem, followed by a hint, and exits with status `2`:

  ```text title="Phone"
  $ fplinux-present --input /run/frame.nv16 --mode rgb
  fplinux-present: --mode must be nv16 or cpu-rgb565
  Try 'fplinux-present --help' for more information.
  ```

- A failure after the command line has been accepted exits with another nonzero status and reports the cause on standard error.

## Where to keep files

Keep inputs and outputs in `/run` or `/tmp`. Both are RAM filesystems: they are always writable, but they use phone memory and are emptied when the phone shuts down. Copy files between the PC and the phone as described in [Connect from a PC](/fplinux/use/connect/). To keep files across boots, use a [microSD card](/fplinux/use/microsd/).
