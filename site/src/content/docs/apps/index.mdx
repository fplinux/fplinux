## Where the applications work

See the [application comparison](/fplinux/phones/#application-support) for a quick overview and [phone support status](/fplinux/phones/#support-status) for each phone's requirements and limitations.

## Install an optional application

Follow [Optional packages](/fplinux/guides/packages/) to copy and install the application's APK and its required libraries from the same build. In a RAM boot, an installed application lasts until the phone shuts down. On a [microSD system card](/fplinux/guides/microsd-system-card/), it stays installed until you remove it. No optional application starts by itself. Exit an application before removing it.

## Start an application

Open graphical applications from the [application catalog](/fplinux/use/session/#home-and-applications). Open [Java and MRE programs](/fplinux/apps/java-and-mre/) by selecting their files in Files. For command-line tools, run their commands in the [USB shell](/fplinux/use/connect/); `--exec` returns when the command exits and shows its output.

TyrQuake, `fplinux-present` and the `fplinux-rotate` preview use the display directly. Follow the [direct-display procedure](/fplinux/use/session/#direct-display-applications) to stop the graphical session before starting them and restart it afterwards. Exiting one of these applications does not restart Home.

## Choose a renderer

In ARMADA, choose **Renderer** on its [setup screen](/fplinux/apps/armada/#start) before starting. TyrQuake accepts `--renderer auto|software|gpu` in the USB shell. Auto uses the installed GPU add-on when a supported hardware context is available and falls back to software when the add-on is absent or GPU initialization fails.

- **Software** uses the CPU and works without Mesa installed.
- **GPU** requires the hardware renderer and reports an error when it cannot start.

ARMADA displays a renderer error in its window; choose Software to continue. A TyrQuake rendering error ends the application and reports the cause in the shell.

The [Xiaomi Qin 1s+](/fplinux/phones/xiaomi-qin-1s-plus/#applications) provides compatible GPU hardware. Its image includes ARMADA's GPU resources; TyrQuake needs the optional `fplinux-tyrquake-gpu` add-on. GPU output in ARMADA's graphical window has not been checked on a phone. GPU mode does not guarantee a higher frame rate. Other supported phones use software rendering.

## Command-line behavior

The FPLinux image tools, ARMADA and Quake launcher follow these command-line rules. FFmpeg uses its own syntax; see `ffmpeg -h` for help.

- `-h` or `--help` prints the usage and every option, then exits with status `0`. It does not open a device or start any work.
- An option value can follow a space or an equals sign: `--output FILE` and `--output=FILE` are the same. Values cannot be empty.
- The image tools accept a repeated value option and use its last value. Every occurrence must still be valid. The other applications reject a repeated option.
- A command-line error prints the command name and the problem, followed by a hint, and exits with status `2`:

  ```text title="Phone"
  $ fplinux-present --input /run/frame.nv16 --mode rgb
  fplinux-present: --mode must be nv16 or cpu-rgb565
  Try 'fplinux-present --help' for more information.
  ```

- A failure after the command line has been accepted exits with another nonzero status and reports the cause on standard error.

## Where to keep files

The [Files application](/fplinux/use/files/) provides **My files** in `/home/fplinux/Files`. Files in the home directory last until power-off in a RAM boot; a microSD system card keeps them across boots. `/run` and `/tmp` remain temporary RAM storage in every profile. Copy files between the PC and the phone as described in [Connect from a PC](/fplinux/use/connect/). A supported [microSD data card](/fplinux/use/microsd/) also keeps files across boots.
