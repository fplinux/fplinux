A standalone archive runs FPLinux without a source checkout or build tools. Pick the ZIP for your PC from the [Releases page](https://github.com/fplinux/fplinux/releases), then select your exact phone in its launcher. Check the phone's [support status](/fplinux/phones/#support-status) and [phone page](/fplinux/phones/) for feature, storage and power limits.

You can also [build and package the same format](/fplinux/develop/packaging/) locally, including a ZIP with only one phone. Follow the instructions in its `README.txt`.

Release ZIPs are named `FPLinux-linux-x64-<release_id>.zip` and `FPLinux-windows-x64-<release_id>.zip`. The twelve-character ID also appears in Settings → About → Build on the phone. Check downloads against the Release's `SHA256SUMS`, then keep the matching source ZIP available when distributing a runnable archive.

:::note[Verification limits]

Checksums establish that downloaded files match their listed bytes. Packaging and launcher checks without a connected phone do not establish phone operation, USB driver installation or loading. Use the phone page's current status for hardware results.

:::

## Start in RAM

The ZIP includes the shared system and kernel, each phone's files, Python, OpenSSH and license notices. The launcher assembles the selected model's bundle in the [working data directory](/fplinux/start/build/#working-data-directory) and prints the location of its optional APKs. Prepared phone data is stored separately. The launcher only reads the phone's internal storage.

The archive includes any required extraction tools. It reuses compatible inputs and prepared data from your [personal phone data store](/fplinux/guides/device-data/#where-phone-data-is-stored), including data saved by another archive or checkout. On first use, UMS9117 targets with required runtime data save a read-only NAND backup and Qin saves selected sound files from eMMC. Targets without required runtime data start Linux and open SSH immediately.

USB loading and SSH from Windows are unverified on Xiaomi Qin 1s+.

### What you need

- A Linux x86-64 PC with coreutils, iproute2, udev and a network manager that automatically runs IPv4 DHCP on a new USB network interface, such as NetworkManager; or a Windows 10 or 11 x64 PC with Windows PowerShell.
- A USB data cable that fits your phone.
- For a UMS9117 target that requires a backup, enough free space for the full internal-storage backup in your personal phone data store.

Python and OpenSSH are bundled; no separate installation is needed. On Linux, the launcher asks for administrator access once if the included USB access rules need to be installed; this step requires `sudo`. On Windows, it can ask to set up the phone's USB driver: read the described driver and certificate changes, confirm them with the checkbox and approve the administrator prompt. Run the launcher as your regular user.

### First run

<Steps>

1. Extract the whole archive and keep the phone powered off and disconnected.

2. Start the launcher from the extracted directory. On Linux:

   ```sh title="PC"
   sh Run.sh
   ```

   On Windows, double-click `Run.cmd`.

3. Select your model by number or target ID. Choose **Start in RAM** if the launcher offers more than one action. Wait for its connection instructions, then hold the indicated boot key and connect the powered-off phone, keeping the key pressed.

4. Keep USB connected. If compatible saved inputs are available, the launcher prepares data from them as needed and continues to Linux and SSH. Otherwise, it reads the required data from your phone. UMS9117 shows the progress of its full NAND backup; Qin reads its selected sound files. Wait until preparation and the storage check finish.

5. If the launcher prints **`Disconnect USB.`**, disconnect the cable. If the phone stays on, briefly remove and reinsert its battery. Run the launcher again with the phone powered off. This restart is needed only after reading new data from the phone.

</Steps>

Private connection keys and launcher logs are kept under `.data/` beside the extracted launcher. `FPLINUX_DATA_DIR` selects another [working data directory](/fplinux/start/build/#working-data-directory), with relative paths anchored to the archive. It must allow execution of the selected bundle's host tools. Each archive and selected model has separate session state. Keep the archive location and selected directory unchanged while reconnecting.

Backups and prepared data use the separate [personal store](/fplinux/guides/device-data/#where-phone-data-is-stored), which survives replacing the archive. Use each store with one physical phone. For another handset of the same model, select its store with `run TARGET --phone-data PATH`.

Each launch prints the exact path to its `runtime.log`, with `run.json` metadata beside it. The log includes launcher and USB loader diagnostics, but does not record your interactive SSH commands or terminal output. If preparation cannot verify that storage is safe to disconnect, it retains reader-session keys in the same working data directory. Keep the phone powered and retain that directory. Run the launcher again to repeat the storage check. `console` selects a running FPLinux session after preparation.

### Subsequent runs

Use the same `sh Run.sh` on Linux or `Run.cmd` on Windows for every later launch. If your phone is still running FPLinux, connect it to resume SSH with its saved keys. This also works if you reconnect USB after starting the launcher. For a fresh boot, keep the phone powered off and disconnected until the launcher displays the connection instructions. Then connect it with its boot key held. The launcher loads FPLinux with your prepared phone data and opens an SSH shell.

If SSH loses its connection during an interactive shell and the phone stays powered, the launcher waits for the same phone to return, verifies its connection and opens a new shell. It does not repeat commands from the interrupted shell. Reconnect USB if disconnected before the wait times out, or open the launcher again afterward. Ctrl+C cancels the wait. Interactive SSH status 255 starts this recovery; use `exit 0` to close the shell unconditionally.

Type `exit` or press Ctrl+D to close the shell. Linux keeps running on the phone. Select the model again in the launcher or use `console` to [reconnect or run a command](/fplinux/use/connect/). One interactive session per model can use that archive's saved connection at a time. Ctrl+C cancels loading or waiting, but does not power the phone off.

The matching `FPLinux-<release_id>-sources.zip` contains the project sources, selected upstream originals and host rebuild material. Both hosts use the source ZIP from the same distribution. Follow the filename in `README.txt`. Component licenses remain in the runnable archive. Dependency inputs for rebuilding are separate Release assets; see [Dependency snapshots](/fplinux/guides/dependencies/).

### Prepare from an existing backup

For UMS9117, you can select a complete physical NAND backup of the same phone for a RAM launch. On Linux:

```sh title="PC"
sh Run.sh run nokia-ta1618 --from-dump /path/to/nand.bin
```

On Windows, open a terminal in the extracted directory:

```bat title="PC"
Run.cmd run nokia-ta1618 --from-dump "C:\path\to\nand.bin"
```

Replace `nokia-ta1618` with your model's target ID. Keep the backup's `nand.bin.json` receipt beside it. The launcher preserves both input files and prepares the data in your personal store before booting. Keep the phone disconnected until the loader asks for it. Use `prepare` in place of `run` to prepare data and stop there.

For Qin, use the same option with a complete eMMC USER-area image containing GPT. The launcher extracts the selected sound files without changing or copying the whole image. A NAND image or a single partition is not an eMMC USER-area image.

On a running phone with NAND support, use `nand identify --target TARGET` or `nand backup FILE --target TARGET` through the same launcher. See [Device data](/fplinux/guides/device-data/) for backup contents and storage.

For machine-readable progress when starting the phone from the command line, add `--events PATH` to `run`. See [Loader events](/fplinux/start/run/#for-automation-loader-events).

## Use a microSD system card

For UMS9117 models with a system-card profile, the Linux and Windows launchers offer **Install on microSD** and **Start from microSD**. Installation erases the selected microSD after confirmation. Follow [microSD system card](/fplinux/guides/microsd-system-card/) to install, start and safely shut down the card.

## Connection order and shutdown

For a fresh USB load, connect the phone only when the launcher asks. If you connected it too early, disconnect it, power it off and start again. To reopen SSH to the same running phone, leave it connected or reconnect USB while the launcher is waiting.

Exiting a launcher or shell leaves Linux running. To end the session without losing data, follow [Power](/fplinux/use/power/). Without a battery, disconnecting USB cuts power immediately.
