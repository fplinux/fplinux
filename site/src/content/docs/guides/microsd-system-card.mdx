The microSD system card keeps the Linux system, installed packages, Bluetooth pairings and your files across power cycles. A Windows or Linux ZIP can install and start the system card for the UMS9117 models that offer these actions. Check your [phone page](/fplinux/phones/) for hardware verification, card limits and features tested only in RAM.

During a USB start, the profile determines which parts come from the PC and which come from the card:

| Target | Profile | Loaded over USB | Read from the card |
| --- | --- | --- | --- |
| UMS9117 targets with system-card support | `microsd-uboot` | U-Boot | Linux boot image and ext4 system root |
| Xiaomi Qin 1s+ | `microsd-root` | Linux | ext4 system root |

The Qin ZIP starts FPLinux in RAM. For a Qin system card, use the [manual image procedure](#build-the-card-image) from a Linux source checkout.

## Install using the phone

Leave the microSD card in the powered-off phone. Open `Run.cmd` on Windows or `sh Run.sh` on Linux from the extracted [Release ZIP](/fplinux/guides/standalone-archive/). Choose your phone and **Install on microSD**. Connect only when prompted. The launcher displays the card it found and asks before erasing it.

FPLinux prepares the phone data on the PC and reuses a compatible saved backup. The installer shows the space for shared files and the system, then writes and verifies the system and your phone's data from the same RAM session. It installs the [initial applications](/fplinux/guides/packages/) from the release's signed catalogue before making the card bootable. Wait for the success message and power off the phone before booting the card. This operation erases the entire selected microSD.

The installer also sets up SSH for your user account on the installing PC. Save the connection command it prints. The private client key and the card's SSH host key pin are saved together with `ssh_config` under `$XDG_DATA_HOME/fplinux/cards/` on Linux (`~/.local/share/fplinux/cards/` by default) or `%LOCALAPPDATA%\FPLinux\cards\` on Windows. Each installation has its own directory under the target ID and card CID. The files stay available after you close the launcher or reboot the computer.

For commands without the menu, first inspect the card with the exact target ID. `inspect` reports the card's CID and capacity from the RAM reader. Keep the phone powered and connected while running the install command. Replace `CID` with the identifier printed by `inspect`.

```bat title="Windows PC"
Run.cmd card inspect inoi-240-modern-4g
Run.cmd card install inoi-240-modern-4g --erase-card CID
```

```sh title="Linux PC"
sh Run.sh card inspect inoi-240-modern-4g
sh Run.sh card install inoi-240-modern-4g --erase-card CID
```

Add `--from-dump FILE` to import a backup for this handset. The source checkout uses the same installer with locally built card files:

```sh
./fplinux card install inoi-240-modern-4g
```

Use `./fplinux card inspect inoi-240-modern-4g` to discover the card before passing `--erase-card CID` in a non-interactive checkout session. Inspection builds only the RAM profile.

## Update or roll back from the PC

Boot a freshly installed card once and wait for the graphical session to become ready. For an update, power off the phone with the card fitted and open the extracted ZIP for the new release. Choose your model and **Update microSD**. Connect when prompted and confirm the displayed CID. The update keeps your files, SSH access and application choices. Applications you removed stay removed. New applications in the initial selection are available in the [APK catalogue](/fplinux/guides/packages/). If a selected package cannot be installed from the new release, the update stops before writing to the card.

Before writing to the card, the reader checks that the new release can restore your additional APK selections. It names the selections that prevent the update.

For a rollback, choose **Select a previous microSD build** and enter its confirmed build ID. `verify TARGET --boot microsd` reports the build ID and mounted slot of the running system. Keep the previous build ID before updating so you can select it from the RAM reader even if the new build cannot boot.

If the reader reports that the card journal needs recovery, select the previous confirmed build from the RAM reader before retrying the update.

The same actions are available as commands, for example on Linux:

```sh title="Linux PC"
sh Run.sh card update inoi-240-modern-4g --card CID
sh Run.sh card rollback inoi-240-modern-4g --card CID --build-id ID
```

Use `Run.cmd` on Windows or `./fplinux` from a source checkout with the same arguments. Wait for the writer to finish and unmount the card before powering off the reader.

## Boot from the card

From the extracted archive, open the launcher, select your model and choose **Start from microSD**. Keep the prepared card in the powered-off phone and connect USB only when the launcher asks for it. You can start the same card on Linux or Windows and keep the same installed system and files. Use the archive for the release you installed.

To start from the command line:

```bat title="Windows PC"
Run.cmd run inoi-240-modern-4g --boot microsd
```

```sh title="Linux PC"
sh Run.sh run inoi-240-modern-4g --boot microsd
```

For another model, use its target ID. Keep `--boot microsd` with `console` and `verify` for the running card session. Follow [Connect from a computer](/fplinux/use/connect/) for shell and transfer commands.

The UMS9117 system card includes an autonomous bootloader. Starting it requires the phone's firmware to support starting from a microSD card. On the tested INOI 240 Modern 4G, leave the card and battery installed and disconnect USB. Hold `*`, `0`, `7` and the red power key until startup begins. This uses the same installed system and files as a USB start. Check your phone's status before attempting autonomous startup on another model.

### Connect over SSH after autonomous startup

After FPLinux starts from the card, connect the USB cable to the installing PC. Wait for the USB network to connect, then run the SSH command printed during installation in a Linux terminal or Windows PowerShell. SSH opens a root shell using the saved client key and checks the card's host key against the saved pin. No password is needed. A card installed through this workflow uses USB NCM for a Linux installer or RNDIS for a Windows installer.

The launcher can also verify or connect to a specific enrolled card. Replace the example CID with the 32 lowercase hexadecimal digits reported for your card during installation, and choose the exact target and release running on it.

```sh title="Linux PC"
sh Run.sh verify inoi-240-modern-4g --card 0123456789abcdef0123456789abcdef
sh Run.sh console inoi-240-modern-4g --card 0123456789abcdef0123456789abcdef
```

Use `Run.cmd` on Windows or `./fplinux` from a source checkout. `--card` selects the `microsd-uboot` profile. Verification checks the kernel, boot recipe, installed build and mounted root slot. If you intend to inspect a different build, add `--allow-other-build` to `console`. The enrolled card and its SSH pin are still required.

These commands also accept a card started with `run TARGET --boot microsd` from the same launcher installation. That startup uses the launcher's transient authenticated USB session. The commands check the mounted CID and the card enrollment over that connection. After autonomous startup, they use the card's saved SSH credentials directly.

If you wrote a generic `FPLINUX.img.xz` manually, use the USB-assisted start for a shell. The generic image has no saved SSH enrollment for autonomous startup.

## Build the card image

Prepare any phone data you want in the system card from the checkout you will build; see [Device data](/fplinux/guides/device-data/). Another checkout may have refreshed the shared personal store with different preparation inputs. UMS9117's automatic preparation uses the default RAM build. Run `device-data prepare` in the selected checkout, then build the system-card profile explicitly. The RAM data capsule does not update firmware or the boot image on a card that is already written.

For a supported UMS9117 phone, use its exact target in place of `nokia-ta1618`:

```sh title="PC — UMS9117"
./fplinux build nokia-ta1618 --profile microsd-uboot
```

For the Xiaomi Qin 1s+, select its profile explicitly:

```sh title="PC — Xiaomi Qin 1s+"
./fplinux build xiaomi-qin-1s-plus --profile microsd-root
```

The build directory printed after `output:` contains `FPLINUX.img.xz`, a compressed image of a whole card. The build never writes to a card. To find the directory later, run `./fplinux inspect bundle` with the same target, profile and build type and read its `bundle:` line.

## Prepare the card

`FPLINUX.img.xz` is a complete disk image with its own partition table, not a file to copy onto an existing filesystem. Writing it replaces the card's partition table and everything on the card.

| Profile | Partition | Initial size | Filesystem | Label | Contents |
| --- | --- | --- | --- | --- | --- |
| `microsd-uboot` | 1 | 2 GiB | FAT32 | `FPLBOOT` | shared files and the autonomous boot entry |
| `microsd-uboot` | 2 | 64 MiB | ext4 | `FPLROOT` | system slots and their boot images |
| `microsd-root` | 1 | 64 MiB | FAT32 | `FPLDATA` | shared files |
| `microsd-root` | 2 | 512 MiB | ext4 | `FPLROOT` | the system, mounted as `/` |

On the first boot, Linux extends partition 2 and its filesystem to the end of the card. Later boots leave a full-size partition unchanged.

:::caution[Write the right card, then check it]

For manual installation, decompress `FPLINUX.img.xz` and write the whole image to the card device itself, not to one of its partitions. Select the intended removable card explicitly. Before the first boot, read the complete image back from the card and compare it with the original.

:::

Never write the image from a system that runs from the same card. To rewrite a system card inside the phone, boot the default RAM system first, stop everything that uses the card and unmount all of its filesystems. Read the image back and compare it before the next microSD boot.

## Boot from a checkout

<Steps>

1. With the phone powered off, insert the prepared card.

2. Start the loader with the profile you built and connect the phone when it asks, as in [Run FPLinux](/fplinux/start/run/). Choose the command for your phone:

   ```sh title="PC — UMS9117"
   ./fplinux run nokia-ta1618 --profile microsd-uboot
   ```

   ```sh title="PC — Xiaomi Qin 1s+"
   ./fplinux run xiaomi-qin-1s-plus --profile microsd-root
   ```

   On UMS9117, `--boot microsd` is an alternative to `--profile microsd-uboot`. It always selects that profile and cannot select Qin's `microsd-root`. Use either `--boot` or `--profile`, not both.

3. Leave the card in the phone for the whole session.

</Steps>

When [reconnecting](/fplinux/use/connect/) or [checking the running build](/fplinux/start/run/#check-which-build-is-running), pass the same profile and build type you selected.

## What persists

Everything on the ext4 root survives a cold start: installed [packages](/fplinux/guides/packages/), Bluetooth pairing records and your files. Files in RAM filesystems such as `/tmp` do not.

## Shared files

Open **Files → Places → Shared files** to connect the FAT32 data folder of the installed system card. Only the `Shared` folder is exposed at `/mnt/card`. Files in **My files**, installed apps and settings remain on ext4.

Files verifies that the FAT32 partition and the running ext4 root are on the same system card before offering the folder.

The stock firmware can open the same `Shared` folder if it supports the system card's partition layout. Shut down before switching systems. If the stock firmware asks to format the card, cancel the prompt. Leave the boot files outside `Shared` in place. Updates and rollbacks preserve the shared folder.

To disconnect the folder in FPLinux, close the apps that use it and choose **Disconnect shared files** in Places. The card stays in the phone while FPLinux runs.

## Shut down

The system card cannot be unmounted or removed while Linux runs, and `sync` alone does not make it safe to cut power. Before you cut power or remove the card, shut down as described in [Power](/fplinux/use/power/).
