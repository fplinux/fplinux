## Phones and hardware

### UMS9117

The Unisoc chip used by several supported phones, also known by its reference name T117. See [UMS9117 features](/fplinux/platforms/ums9117/).

### SC9820E

The Unisoc chip used by the Xiaomi Qin 1s+. See [SC9820E features](/fplinux/platforms/sc9820e/).

### Platform

The code shared by phones with the same chip. FPLinux has the `ums9117` and `sc9820e` platforms.

### Target

The description of one exact phone model, and the name you pass to `./fplinux build` and `./fplinux run`, such as `nokia-ta1618`. A target is never used for a different model. See [Phones](/fplinux/phones/).

### Support status

The result for one function on one exact phone, with its tested conditions and remaining limits. See the [phone status legend](/fplinux/phones/#support-status). Hardware presence is a separate fact.

### Implementation status

Whether FPLinux provides a function on a particular platform. This does not establish a device result or support on every model. See [Features](/fplinux/features/#status-meaning).

### Stock firmware

The software the phone came with. Starting the phone normally, without the boot key, starts it.

### Internal storage

The phone's built-in flash memory, which holds the stock firmware. Targets with a read-only NAND interface can prepare [device data](/fplinux/guides/device-data/) and backups. Other targets provide no internal-storage access.

### Device data

Radio firmware and calibration, Bluetooth records, FM settings and audio tuning from your own phone. FPLinux does not ship these inputs. Target-owned board initialization and Linux keymaps are separate. See [Device data](/fplinux/guides/device-data/).

## Loading the phone

### Loader

The PC side of a start: `./fplinux run` in a source checkout, or `fplinux.py run` in a [standalone archive](/fplinux/guides/standalone-archive/). The shared runtime prepares required UMS9117 RAM data on first use, sends FPLinux over USB and opens SSH. Qin and headless UMS9117 targets without runtime data groups boot directly. Running the same command again reopens an authenticated live session. See [Run FPLinux](/fplinux/start/run/).

### Boot key

The key you hold while connecting USB to a powered-off phone so that it waits for a load instead of starting its stock firmware. Use the exact key listed on your [phone page](/fplinux/phones/).

### BootROM

Code built into the chip that runs first. With the boot key held, it appears on the PC as USB device `1782:4d00` and accepts a load.

### RAM loader (FDL1)

A small program that the loader sends first. It prepares the phone's memory and receives the rest of the system.

### USB network link

The private network over the USB cable that the shell, file copies and the PC keyboard use once Linux runs. The phone then appears as USB device `0525:a4a6`. See [Connect from a computer](/fplinux/use/connect/).

### RAM system

The default build. It runs entirely from the phone's RAM and forgets everything at power-off.

### microSD system card

A build that keeps the Linux system on a microSD card, so packages and files persist. Each cold start still needs the PC loader. UMS9117 uses U-Boot to start Linux from the card; SC9820E loads Linux over USB and mounts the card as its root. See [microSD system card](/fplinux/guides/microsd-system-card/).

## Builds and packages

### Profile

The boot mode a build is made for: the RAM system by default, or a microSD system card with `microsd-uboot` on supported UMS9117 targets and `microsd-root` on Qin. Check your phone's supported profiles and pass the same `--profile` to every command for that build.

### Build type

`release` by default, or `debug`, which adds kernel diagnostics. See [Debugging](/fplinux/develop/debugging/).

### Optional package

An application delivered as an APK file and installed on a running phone with `apk`. See [Optional packages](/fplinux/guides/packages/).

### Standalone archive

A packaged FPLinux for one phone that runs without a source checkout or build tools. See [Standalone archive](/fplinux/guides/standalone-archive/).

### Candidate

A standalone archive packaged for testing whose exact executable payload has no recorded phone-tested release status. It is marked by `CANDIDATE-NOTICE.txt` and must not be published as a release. See [Packaging](/fplinux/develop/packaging/).
