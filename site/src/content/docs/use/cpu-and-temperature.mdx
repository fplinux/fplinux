## CPU speed

<FeatureStatus feature="manual-cpu-frequency-selection" />

[UMS9117](/fplinux/platforms/ums9117/) phones run at 1 GHz by default; the [SC9820E](/fplinux/platforms/sc9820e/) Xiaomi Qin 1s+ runs at 1.3 GHz. Where manual switching is supported, you can select 768 MHz. There is no automatic speed scaling or voltage reduction. Check your [phone's support status](/fplinux/phones/#support-status) before switching.

Switch to 768 MHz, check the result, then return to the default:

```sh title="Phone"
cd /sys/devices/system/cpu/cpufreq/policy0
default_frequency=$(cat cpuinfo_max_freq)
echo userspace > scaling_governor
echo 768000 > scaling_setspeed
cat cpuinfo_cur_freq
echo "$default_frequency" > scaling_setspeed
cat cpuinfo_cur_freq
echo performance > scaling_governor
```

Values are in kHz. Read `cpuinfo_cur_freq` to check the hardware setting after a request. A successful write to `scaling_setspeed` alone does not establish that the transition succeeded. Both Qin cores share one frequency policy.

On UMS9117, `fplinux-cpuclock` runs a short timing loop and prints a lower-bound estimate of the actual clock speed. It is a diagnostic aid, not a benchmark; run `fplinux-cpuclock --help` for its options.

## Temperature

<FeatureStatus feature="soc-temperature" />
<FeatureStatus feature="auxiliary-adc" />

Temperature sensors measure different things on the two platforms. Use only the sensor available on your [phone](/fplinux/phones/):

| Platform | Thermal zone `type` | Reading |
| --- | --- | --- |
| UMS9117 | `ums9117-thermal` | Processor chip temperature |
| SC9820E, Xiaomi Qin 1s+ | `board-thermal` | Board thermistor temperature, not CPU temperature |

Read each available zone's name and temperature in thousandths of a degree Celsius:

```sh title="Phone"
for zone in /sys/class/thermal/thermal_zone*; do
  [ -d "$zone" ] || continue
  printf '%s: %s\n' "$(cat "$zone/type")" "$(cat "$zone/temp")"
done
```

A value of `41500` means 41.5 °C. Absolute accuracy has not been checked against a thermometer. Neither reading provides automatic CPU thermal protection: FPLinux does not slow the processor down or take action based on it.
