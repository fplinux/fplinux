Control the screen brightness, keypad light and vibration through the interfaces below. Check [support status](/fplinux/phones/#support-status) and your [phone page](/fplinux/phones/) before using a control; their availability and visible results depend on the phone.

## Display

The display has a fixed native size, listed on the selected [phone page](/fplinux/phones/). RGB565 images use two bytes per pixel and packed rows. The display does not scale or rotate images; prepare their size and orientation before using the [image tools](/fplinux/apps/#image-tools).

The [graphical session](/fplinux/use/session/) uses Wayland. Applications that present frames directly use the [DRM display interface](/fplinux/develop/device-interfaces/#drm-display) and need the graphical session stopped. The phone pages state the limits of each phone's visible image results.

## Screen brightness

<FeatureStatus feature="lcd-backlight" />

Brightness uses a scale from `0` to `10`; `0` switches the backlight off. The default level is `7`. The graphical session restores its saved brightness when available. Read and change the level in a shell on the phone:

```sh title="Phone"
fplinux-brightness get
fplinux-brightness set 4
```

To change it with the keypad, use **Settings → Display → Brightness** in the [phone interface](/fplinux/use/session/). The optional direct-display [Brightness control](/fplinux/apps/brightness/) application uses the same service.

The brightness service keeps the level during the current boot. Settings saves its selection with the other [session settings](/fplinux/use/session/#settings); those files survive power-off only on a persistent system root. The numbers are settings, not percentages or light measurements, and the same number can look different on different phones.

Restarting the brightness service during the same boot preserves the selected level. Automatic screen-brightness control is not provided.

An application can change the brightness temporarily while it uses the screen. `fplinux-brightness get` keeps reporting your level, and a level you set meanwhile takes effect when the application finishes.

Switching off the backlight leaves the display running. After wake or display enable, the backlight stays off until the first frame is ready.

:::tip[Screen is dark]

If you set level `0`, the screen stays dark. Restore it with `fplinux-brightness set 7` in a shell opened [from your computer](/fplinux/use/connect/), or press <Key>Up</Key> in the Brightness application.

:::

## Keypad light

<FeatureStatus feature="keypad-backlight" />

On phones with automatic keypad lighting, the light turns on when you press a key and turns off about five seconds after the last key press. Input from a connected keyboard counts too. Check [keypad-light support](/fplinux/phones/#support-status) for your phone: manual lighting and automatic lighting from physical keys can have different support states. Most phones expose on/off control; the phone page lists any different brightness range.

On phones with automatic lighting, first disable its trigger:

```sh title="Phone"
echo none > /sys/class/leds/:kbd_backlight/trigger
```

Switch the light on at its maximum level or off:

```sh title="Phone"
cat /sys/class/leds/:kbd_backlight/max_brightness > /sys/class/leds/:kbd_backlight/brightness
echo 0 > /sys/class/leds/:kbd_backlight/brightness
```

A light switched on this way stays on until you switch it off. On phones with automatic lighting, restore its trigger with:

```sh title="Phone"
echo input-events > /sys/class/leds/:kbd_backlight/trigger
```

## Vibration

<FeatureStatus feature="vibration" />

There is no command to make the phone vibrate; applications such as [ARMADA](/fplinux/apps/armada/) use it. Vibration is either on or off, with no adjustable strength, and each vibration stops automatically after about five seconds at most.

The [phone page](/fplinux/phones/) states whether vibration uses a motor or the speaker and whether it is supported. Speaker-based vibration plays a low tone and has additional conditions:

- vibration needs [device data](/fplinux/guides/device-data/) prepared from the same phone; without it, the phone does not vibrate;
- a single continuous vibration lasts at most about three seconds;
- headphone sound, including FM radio, is muted while the phone vibrates and for about a second afterwards; speaker sound keeps playing;
- a running recording picks up the vibration tone.

Developers can find the programming interface in [Device interfaces](/fplinux/develop/device-interfaces/).
