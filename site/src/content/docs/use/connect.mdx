Use the USB link to open a root shell, run commands, copy files with an integrity check and type with your computer's keyboard. Check [support status](/fplinux/phones/#support-status) and your [phone page](/fplinux/phones/) for USB support. The cable used to load FPLinux stays connected as a private link between your computer and the phone.

<FeatureStatus feature="usb-networking" />

Start the phone first, as described in [Run FPLinux](/fplinux/start/run/) or, for a downloaded archive, in [Standalone archive](/fplinux/guides/standalone-archive/). The commands on this page work once that run reports a ready session.

## What the USB link is

The phone appears on your computer as a small USB Ethernet device. Your computer receives its address automatically; do not set addresses by hand or reuse an address from an earlier run. The link carries the shell, file copies and the keyboard bridge described below.

It is not an Internet connection. The phone gets no gateway or DNS over USB and does not forward traffic for your computer. Supported UMS9117 phones can use a [Bluetooth PAN connection](/fplinux/use/bluetooth/) for Internet access. Bluetooth is unsupported on the SC9820E Xiaomi Qin 1s+.

The phone is always the USB device on this cable. It cannot act as a USB host, so USB keyboards, drives and other peripherals cannot be plugged into the phone.

## Open a shell

<Tabs syncKey="source">
	<TabItem label="Source checkout">

```sh title="PC"
./fplinux console <target>
```

    </TabItem>
    <TabItem label="Linux RAM ZIP">

```sh title="PC"
sh Run.sh --reconnect
```

    </TabItem>
    <TabItem label="Windows RAM ZIP">

```bat title="PC"
Run.cmd --reconnect
```

    </TabItem>
    <TabItem label="Linux system-card export">

```sh title="PC"
python3.14 -I fplinux.py run --reconnect
```

    </TabItem>

</Tabs>

You get a root shell. It is authenticated with a key created for the current session. Password login, port forwarding, agent forwarding and X11 forwarding are disabled. Leaving the shell with `exit`, or with the OpenSSH escape `~.`, closes only the shell. Linux keeps running.

:::note[Match the running build]

Use the target, profile and build type that started the phone. For a microSD system card, pass the selected `--profile` to every `./fplinux console` and `./fplinux verify` command; see [system-card profiles](/fplinux/guides/microsd-system-card/). For a debug build, also add `--build-type debug`. The defaults select the release RAM build; a command for a different build refuses the session.

:::

## Reconnect after unplugging

Linux keeps running after you unplug the cable only while the phone has another power source, such as a battery. Plug the cable back in and run the same command as above. FPLinux checks that the phone still runs the same session and image before it opens the shell. Do not load the phone again just to restore the link.

Without a battery, unplugging the cable cuts the phone's power. Before you unplug, follow [End the session safely](/fplinux/use/power/).

A power-off or a new load starts a new session, and the connection details of the old one no longer apply. Commands and file copies that were interrupted are not repeated automatically.

## Run one command

Use `--exec` when you do not need an interactive shell. The command runs on the phone; its output and exit status come back to your computer.

<Tabs syncKey="source">
	<TabItem label="Source checkout">

```sh title="PC"
./fplinux console <target> --exec 'uname -r'
```

    </TabItem>
    <TabItem label="Linux RAM ZIP">

```sh title="PC"
sh Run.sh --reconnect --exec 'uname -r'
```

    </TabItem>
    <TabItem label="Windows RAM ZIP">

```bat title="PC"
Run.cmd --reconnect --exec "uname -r"
```

    </TabItem>
    <TabItem label="Linux system-card export">

```sh title="PC"

```

    </TabItem>

</Tabs>

Stopping the local `--exec` client can leave a silent command running on the phone. Use bounded commands where possible. If you interrupt one, reconnect and stop that command explicitly before ending the session.

## Copy files

<FeatureStatus feature="file-transfer" />

On a Linux PC, upload a file to the phone or pull one from it. The Windows launcher does not support file transfer.

<Tabs syncKey="source">
	<TabItem label="Source checkout">

```sh title="PC"
./fplinux console <target> --upload ./song.wav /tmp/song.wav
./fplinux console <target> --pull /tmp/recording.wav ./recording.wav
```

    </TabItem>
    <TabItem label="Linux RAM ZIP">

```sh title="PC"
sh Run.sh --reconnect --upload ./song.wav /tmp/song.wav
sh Run.sh --reconnect --pull /tmp/recording.wav ./recording.wav
```

    </TabItem>
    <TabItem label="Linux system-card export">

```sh title="PC"
python3.14 -I fplinux.py run --reconnect --upload ./song.wav /tmp/song.wav
python3.14 -I fplinux.py run --reconnect --pull /tmp/recording.wav ./recording.wav
```

    </TabItem>

</Tabs>

Use these commands rather than a separate SFTP client when the result matters. They guarantee that:

- the complete file's size and SHA-256 are checked before it appears at the destination;
- the destination file appears whole, never partially written;
- if any step fails, the destination is left unchanged.

The source must be a regular file. On the phone, give an absolute path in a directory that already exists and has enough free space. On your computer, the destination directory must already exist. A pull also checks that the phone's source file did not change during the transfer.

Limits:

- A copy does not resume after an interruption; start it again.
- Only regular files can be copied, not directories or raw devices.
- A destination in RAM, such as `/tmp`, uses the phone's limited memory and disappears when the phone powers off. To keep files, copy them to a mounted [microSD card](/fplinux/use/microsd/).

### Files for graphical applications

Open **Files → My files** on the phone first to create its folder. Upload your file to `/home/fplinux/Files/`, using its full destination path, such as `/home/fplinux/Files/program.jar`.

Uploads belong to `root`, while graphical applications use the `fplinux` account. After uploading, run this command in the phone's SSH shell so the application can read and update the file:

```sh title="Phone SSH"
chown fplinux:fplinux /home/fplinux/Files/program.jar
```

Replace `program.jar` with your file's name and repeat this step for any companion files you uploaded. Then open the file in [Files](/fplinux/use/files/).

## Type with your computer's keyboard

<FeatureStatus feature="host-keyboard-bridge" />

The bridge is available on supported [UMS9117](/fplinux/platforms/ums9117/) phones; use it only where your phone checklist lists support for the current profile. The [SC9820E Xiaomi Qin 1s+](/fplinux/platforms/sc9820e/) uses SSH for PC command input and does not support this bridge.

The PC keyboard tool is supplied by a source build or a Linux system-card export. RAM ZIPs do not include it.

The keyboard bridge forwards one keyboard from your computer to the phone. On the phone it behaves like any other keyboard: it controls the [graphical interface](/fplinux/use/session/) and types into its text fields, or into direct-display applications such as [TyrQuake](/fplinux/apps/tyrquake/) when the graphical session is stopped.

:::caution[The forwarded keyboard is captured]

While the bridge runs, that keyboard's keys no longer reach your computer's desktop or terminal, including the terminal where you started the bridge. Use a second keyboard if you can. Otherwise keep the `timeout` shown below, so the keyboard is released automatically.

:::

<Tabs syncKey="source">
	<TabItem label="Source checkout">

```sh title="PC"
sudo timeout 60s ./fplinux console <target> --keyboard /dev/input/eventN
```

    </TabItem>
    <TabItem label="Linux system-card export">

```sh title="PC"
sudo timeout 60s ./host/fplinux-usb-keyboard \
  --interface 0 --keyboard /dev/input/eventN
```

    </TabItem>

</Tabs>

Replace `/dev/input/eventN` with the input device of the keyboard to forward. On most Linux computers, `ls -l /dev/input/by-id/` lists keyboards under names ending in `-event-kbd`, and you can pass that path instead. Root privileges are usually needed to open the keyboard and the USB interface.

The bridge can run alongside a shell, a single command or a file copy. If the cable or the keyboard is disconnected, the phone releases all forwarded keys, so no modifier stays held. Stopping the bridge releases the keyboard on your computer.

## Plain OpenSSH (advanced)

From a source checkout, a ready session also has an OpenSSH configuration that works only for that session:

```sh title="PC"
ssh -F ".cache/runtime/<target>/session/current/<target>.ssh-config" fplinux
```

It pins the keys of the current session. Do not copy it to a later session or use it as a general phone login. Use the [reconnect command for your checkout or archive](#open-a-shell) to check that the target and running image still match before opening SSH.
