Include the installed headers under `fplinux/` and link with `pkg-config --cflags --libs fplinux-ui`. Use the complete workflow in [Your first application](/fplinux/develop/app/first-app/) before adding custom rendering or media. Headers specify exact argument ranges, return values and error codes; the guides explain how to combine the interfaces.

## Interface map

| Header | Use |
| --- | --- |
| `fplinux-ui.h` | Runtime, events, geometry, theme, glyphs, images and session actions |
| `fplinux-ui-screen.h` | Screens, commands, stack navigation, forms and Canvas |
| `fplinux-ui-text.h` | Shared text field in a custom screen |
| `fplinux-ui-menu.h` | A low-level popup menu for custom content |
| `fplinux-ui-symbol-picker.h` | Shared centred symbol grid for a custom input consumer |
| `fplinux-ui-prefs.h`, `fplinux-storage.h` | Preferences and explicit save outcomes |
| `fplinux-ui-file-picker.h` | File or folder selection through My files and connected storage |
| `fplinux-ui-recent.h`, `fplinux-ui-view-settings.h` | Recent documents and shared image settings |
| `fplinux-rgb565.h` | Viewport, scaling, rotation and reverse coordinate mapping |
| `fplinux-ui-locale.h` | Localized date and number display |
| `fplinux-ui-frame.h` | Owned RGB565 software frames |
| `fplinux-ui-audio.h` | Playback streams managed by the system |
| `fplinux-ui-system.h` | Confirmed Media, Alarm and brightness levels |
| `fplinux-ui-vibration.h` | System-managed vibration patterns |
| `fplinux-ui-lights.h` | Temporary screen and keypad light effects |
| `fplinux-ui-session.h` | System application messages and raw `fplinux_ui_send()` |

Use high-level screens first. The low-level menu provides one popup, not a page history; [screen navigation](/fplinux/develop/app/screens/#open-return-and-finish) handles return to Options. The private session message transport is for system components, not an application-to-application API.

The system, UI library and optional application APKs use the headers and ABI from the same FPLinux build. Rebuild current clients together when that interface changes. Transport helpers used to implement the session protocol belong to the internal header and are not installed or exported as application APIs.

## Runtime and borrowed data

`fplinux_ui_open()` returns a runtime or null on failure. `fplinux_ui_run()` owns the event loop; `fplinux_ui_close()` releases it. Use UI, LVGL, frame and media functions from the UI thread. Do not start another LVGL event loop or access its objects from a worker thread.

Events are borrowed for the callback. Read their current fields there; do not retain the event pointer. Ignore event types the application does not handle. Theme, metric and glyph pointers belong to the runtime; do not free them or depend on the size of their structures.

Use `fplinux_ui_watch_fd()` for nonblocking file descriptors that need attention in the loop. Each descriptor has its own registration; registering the same fd updates that registration. Check the returned boolean for allocation or argument errors. The application owns the descriptor and calls `fplinux_ui_unwatch_fd()` before closing it. Keep callbacks short. Application timers likewise belong to the application unless a helper explicitly documents ownership.

The [lifecycle guide](/fplinux/develop/app/lifecycle/) owns activation, visibility, resize and closing. The [Application state contract](/fplinux/develop/application-state/) owns save results and close decisions; a successful `prefs_set` only changes memory.

## File selection and program preferences

Open `fplinux_ui_file_picker_open()` over the current screen for a file or destination folder. Supply an absolute My files path and, for files, an optional extension filter. The picker copies its options, reads directories asynchronously and uses the existing storage service for connecting and ejecting cards. Forward results from the application's storage handler to `fplinux_ui_file_picker_storage_result()` while it is open.

The callback runs on the UI thread. A selected path is borrowed until it returns; copy it before retaining it. Selection leaves the picker open so the caller can finish a destination operation or report its error. Close it explicitly when finished. Closing invokes no callback. To open a document in another application, pass the selected path to the existing document API; the picker does not choose or launch a handler.

`fplinux_ui_recent` holds up to ten documents without testing whether they are currently accessible. Record a document after accepting it, then store the model in the application's preferences and check the save result. Removing an entry does not remove its file or data. Shared view settings supply a List of scale and rotation values and exclusive Lists for choosing them. Callers own the choice listener, persistence and the point at which a running program adopts the values.

For per-program overrides, `fplinux_ui_program_prefs_open()` accepts the runtime's own 64-character lowercase hexadecimal identity key. These preferences are separate from guest save files. The runtime remains responsible for its program identity and guest storage format.

`fplinux_rgb565_viewport_init()` defines a centred image rectangle for fit, original-size or integer scaling with 0°, 90° or 270° rotation. Transform strides are in pixels. `fplinux_rgb565_transform()` writes the visible image and leaves margins and row padding untouched; the caller fills its own background. `fplinux_rgb565_map_point()` reports whether a destination point lies inside the image before returning guest coordinates. These functions do not own frame memory or publish a UI frame.

## Low-level menus

For custom content, call `fplinux_ui_menu_open(ui, origin, title, items, count, callback, context)`. Supply `FPLINUX_UI_MENU_ORIGIN_LEFT`, `FPLINUX_UI_MENU_ORIGIN_CENTRE` or `FPLINUX_UI_MENU_ORIGIN_RIGHT`. Left and right origins touch the corresponding edge; centre is centred. OK chooses an item, and the right soft key or Escape means Back in every position. Pass null for an ordinary action menu's title, or a specific title when it helps identify the actions. Applications supply no popup coordinates or dimensions; [layout and appearance](/fplinux/develop/app/design/#use-the-space-you-receive) defines the shared sizing behavior.

Only one low-level menu may be open; another open fails with `EBUSY`. Item texts are copied when it opens. While open, the menu owns input and legends, and the covered content receives no key presses. A release follows the owner of its press. The runtime closes the popup before calling its callback with the chosen action or `FPLINUX_UI_MENU_CANCELLED` for Back. A callback may open a replacement menu; pass the origin again to preserve its position. `fplinux_ui_menu_close()` closes without a callback. Use high-level [screen navigation](/fplinux/develop/app/screens/#open-return-and-finish) when a child page must return to Options and restore its selection.

## Software frames

A `fplinux_ui_frame` owns RGB565 pixel storage and an LVGL canvas. It is not a second window or screen stack. Use it for custom pixel drawing within the existing UI.

- `DIRECT` uses one buffer: finish drawing and presenting without yielding or refreshing LVGL halfway through the paint.
- `STAGED` uses separate drawing and published buffers, so drawing may span callbacks while the previous complete frame remains visible.

Obtain pixels, finish the drawing, mark damage, then present. Stride is the width in pixels. Damage coordinates are inclusive and local to the frame; null damage marks the whole frame. Presenting while the UI is hidden returns an error with `EAGAIN` and retains the damage for a later presentation.

After a geometry change, call `fplinux_ui_frame_resize()`, obtain the pixels again, redraw and mark the entire new frame. Do not retain an old pixel pointer across resize. Failed growth leaves the previous allocation intact; a successful geometry change clears the previous damage and staged image.

`fplinux_ui_frame_object()` returns a borrowed canvas. You may position or reparent it inside the UI, but must not delete it directly. Deleting its parent or closing the UI deletes the canvas and detaches its timer; the frame handle and buffers still need `fplinux_ui_frame_delete()`.

`fplinux_ui_frame_set_timer()` borrows an application-owned timer and pauses or resumes it according to UI visibility and the enabled flag. Detach that timer before deleting it. Covering a particular application screen is not the same as hiding the entire UI: disable work for an inactive Canvas explicitly. API Demos contains a complete software-frame consumer with resize and cleanup.

## Sound

Check `fplinux_ui_audio_supported()` before offering playback. Open a stream with its rate and channel count, write interleaved signed 16-bit native-endian frames, and close it when finished. Mono and stereo rates from 8 to 48 kHz are supported; the process can hold at most four streams. The system performs resampling and mixing. Applications do not open ALSA devices or change output routing through this API.

`fplinux_ui_audio_write()` is nonblocking and may accept fewer frames than requested. Counts are frames, not individual channel samples or bytes. Keep unwritten frames for a later callback instead of busy-waiting. `EPIPE` means the stream has ended; close it and open a new one when appropriate.

Hiding an ordinary application pauses its streams while keeping queued frames; showing it resumes them. An installed desktop entry may request `X-FPLinux-BackgroundAudio=true`. Session grants at most one background audio owner; check `fplinux_ui_audio_background_supported()` for the current grant, including after a runtime CONFIG update. This permission does not allow background vibration or recording. Closing or crashing an application ends its streams.

Use `fplinux_ui_audio_pause()` for user pause without discarding frames. Resuming does not override system policy. `fplinux_ui_audio_status()` distinguishes playing, paused, unavailable and ended streams, with a separate reason. Foreground PCM and alarms can hold background media; opening a silent application does not. A muted alarm still interrupts media. On private-output loss, present Play to explicitly resume; do not silently resume through the speaker.

`fplinux_ui_audio_volume_step()` requests a persistent relative Media change of −1 or +1. A true return means the request was sent. Its asynchronous SETTING or ERROR response is named `media_volume_step` and carries a nonzero serial; a newer step can supersede an outstanding step. It does not grant permission to change other settings. Content-specific gain, such as a guest program's volume, belongs before transport; do not add a second Music master.

Use `fplinux_ui_system_level_get()` to display a confirmed Media, Alarm or brightness level. `FPLINUX_UI_EVENT_SYSTEM_LEVELS` means the runtime has updated its snapshot; read the getter from the callback. READY provides a value and range. UNKNOWN and UNAVAILABLE do not mean zero, and `pending` never turns a requested value into a confirmed one. Before the first snapshot the getter fails with `EAGAIN`. Foreground applications receive changes and a refreshed snapshot when they return; hidden applications are not woken for every level change.

The shell presents temporary feedback for volume keys and application Media steps without taking input focus. Inline settings editors keep their own controls and save results. A level applied successfully but not saved remains the current level; report its storage error separately. Applications do not create or position the system indicator.

Keep file reads and decoding off the UI thread. Existing `fplinux_ui_watch_fd()` callbacks can receive worker results and timerfd playback deadlines while hidden; visual frame timers are visibility-bound and cannot drive background playback. All audio stream calls remain on the UI thread. `fplinux_ui_audio_queued()` includes the output queue: decoder EOF alone does not mean the final frames have played. Closing a stream discards its remaining queue, though a bounded tail already mixed into the output can remain.

The capability check and successful writes do not prove that the physical speaker produced sound. Preserve the distinction between program results and [phone support](/fplinux/phones/#support-status).

## Vibration

Check `fplinux_ui_vibration_supported()`, then submit a bounded pattern through `fplinux_ui_vibration_play()`. Durations alternate pause, pulse, pause, pulse; `{0, 200}` requests an immediate 200 ms pulse. The installed header defines the accepted ranges and repetition rules. Use `fplinux_ui_vibration_stop()` when the visible operation ends.

Vibration is available only to the visible foreground application. Hiding it stops the pattern; returning does not restart it. A vibration request does not wake the display or postpone dimming. Do not assume the phone has a separate motor: the session owns the hardware choice.

A successful request means it was sent. Later execution errors can be reported by the session, and neither response measures a physical effect. An unavailable capability must leave the application's non-vibration actions usable.

## Light effects

An installed application can declare `X-FPLinux-LightEffects=true` in its desktop entry. Check `fplinux_ui_light_effects_supported()` for the available screen and keypad resources, then submit a temporary effect through `fplinux_ui_light_effects_apply()`. The installed header defines the resource mask and level ranges. Applications do not open backlight or LED devices.

Effects belong to the visible foreground application. Hiding, locking or a higher-priority system screen clears them; showing the application does not replay them. Call `fplinux_ui_light_effects_clear()` when the visible operation ends. Clearing restores the current system policy, including the user's latest brightness setting. Effects do not change saved settings.

A true return means the request was sent. An optional output parameter receives its serial for matching the asynchronous confirmation or error. Handle a `not-visible` response by waiting until the operation is eligible and submitting its current effect; do not replay elapsed effects. An unavailable light must leave the rest of the application usable.
